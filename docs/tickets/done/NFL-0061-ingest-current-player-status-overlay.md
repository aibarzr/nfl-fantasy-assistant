## Outcome

The backend can idempotently receive, validate, persist, replay, and report a fresh neutral
player-status snapshot whose provider-specific acquisition and translation remain behind the
extension adapter.

## Context

Current injury information changes independently of an immutable historical dataset. It must not
silently mutate a draft's pinned model inputs, live only in extension memory, or leak raw
provider-shaped records into backend domain logic. Reproducibility requires storing the exact
observed overlay revision used by each recommendation.

## In scope

- Define the canonical neutral status vocabulary, explicit unknown/conflict semantics, source and
  observation timestamps, freshness, snapshot completeness, identity, checksum/revision, and
  idempotency rules in canonical domain and protocol documentation.
- Add the authoritative Pydantic/OpenAPI request and response shapes, generated or checked
  TypeScript consumers, and compatibility behavior before accepting wire traffic.
- Acquire only source-approved fields at the approved cadence inside the provider adapter, reduce
  them to exact mapped IDs and neutral facts, and avoid sending names or raw catalog records.
- Validate snapshot completeness and identity coverage before atomic persistence; reject partial,
  stale, future-dated, conflicting, or version-incompatible observations without replacing the
  last valid snapshot.
- Persist immutable overlay revisions and associate the exact revision and freshness state with
  recommendation provenance and replay.

## Out of scope

- Deciding fantasy-value penalties, excluding players, or predicting recovery.
- Storing provider display names, news text, raw responses, or medical notes.
- Changing historical projection features or replacing the pinned prepared dataset.

## Acceptance criteria

- [x] Platform-specific fields and cadence remain behind the extension adapter; backend application
  and domain code consume only neutral internal models.
- [x] Repeated identical snapshots are idempotent, while changed snapshots create an ordered,
  immutable revision with source, observed-at, received-at, checksum, and freshness provenance.
- [x] Unknown, omitted, stale, incomplete, and contradictory evidence cannot be interpreted as
  healthy or silently overwrite the last valid complete observation.
- [x] Restart and replay reproduce which prepared dataset, model, feature version, and status
  overlay revision were used for a recommendation.
- [x] Protocol documentation, Pydantic/OpenAPI, checked/generated TypeScript types, persistence,
  migrations, and tests remain aligned; any costly boundary decision receives an ADR.
